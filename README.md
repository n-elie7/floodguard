# FloodGuard

FloodGuard is a flood risk monitoring prototype for Kigali, Rwanda. It fetches weather data from Open-Meteo, scores Kigali sectors with an experimental risk index, stores assessments in PostgreSQL with PostGIS, and displays the results on public and officer maps. It also supports opt-in browser push alerts. SMS and email are optional integrations.

> **Prototype notice:** The risk index is not a flood probability or an official warning. Its thresholds have not been validated against observed flood events. Follow guidance from Rwanda's emergency authorities for real safety decisions.

## Run locally with Docker

This is the recommended way to run the complete application. The commands below use a macOS or Linux terminal. On Windows, use PowerShell for the equivalent file operations, then run the same Docker Compose commands.

### 1. Prerequisites

- Docker Desktop with Docker Compose, or Docker Engine with the Compose plugin on Linux
- An internet connection for the first image build, Kigali sector boundaries, Open-Meteo weather data, and OpenStreetMap tiles
- Free local ports **80** and **443**

Java, Maven, Node.js, PostgreSQL, and PostGIS do not need to be installed on your computer for the Docker setup.

### 2. Get the project

```bash
git clone https://github.com/n-elie7/floodguard.git
cd floodguard
```

If you already have the project folder, open a terminal in its root directory instead. Run all Docker Compose commands from that directory.

### 3. Configure the environment

```bash
test -f .env || cp .env.example .env
chmod 600 .env
```

If `.env` already exists, the command keeps it. Open `.env` in an editor. Set different, strong values for `DATABASE_PASSWORD` and `ADMIN_PASSWORD`. Generate `PHONE_ENCRYPTION_KEY` with:

```bash
openssl rand -base64 32
```

Paste the output after `PHONE_ENCRYPTION_KEY=`. Keep `PUBLIC_DOMAIN=localhost` for a basic local run. The map and weather data do not need an API key.

The `.env` file is private and ignored by Git. Keep the phone encryption key and database password stable after you start accepting subscriptions, because changing them can make existing data unusable. Browser alerts also need the VAPID keys described [below](#enable-browser-alerts-locally).

### 4. Build and start the containers

```bash
docker compose config --quiet
docker compose up -d --build
docker compose ps
```

The first build may take several minutes. Compose starts PostgreSQL/PostGIS, the Spring Boot API, the hourly worker, the React frontend, and Caddy. Wait until `db`, `backend`, `worker`, and `frontend` show as healthy. To watch startup:

```bash
docker compose logs -f --tail=100 backend worker
```

Press `Ctrl+C` to stop following logs. This does not stop the containers.

### 5. Open FloodGuard

| Page | Local address | Purpose |
| --- | --- | --- |
| Citizen map | [https://localhost/](https://localhost/) | Check the current risk index for a sector |
| Officer dashboard | [https://localhost/operator](https://localhost/operator) | Inspect sectors, alerts, and operations |

Caddy serves the application on ports 80 and 443 and redirects normal browser traffic to HTTPS. The backend and database are internal to Docker Compose, so there is no separate backend port to open. Caddy creates a local certificate. If your browser does not trust it, install the local Caddy root certificate in your operating system's trust store before testing browser notifications. You can copy that certificate out of the container with:

```bash
docker compose cp caddy:/data/caddy/pki/authorities/local/root.crt /tmp/floodguard-caddy-root.crt
```

Only trust a certificate generated by your own local Caddy container.

On macOS, run `open /tmp/floodguard-caddy-root.crt` and use Keychain Access to import that certificate and mark it trusted. Restart your browser afterward. This step is especially important for local browser push alerts. Other operating systems have their own certificate trust settings.

### 6. Sign in and wait for the first assessment

Sign in on the officer page with `ADMIN_USERNAME` and `ADMIN_PASSWORD` from `.env`. On a new database, FloodGuard requires you to set a new officer password of at least 14 characters. Save that new password. The original value in `.env` will not replace it on later starts.

For the private facilitator demo, sign in at [the officer dashboard](https://dex47dljon83v.cloudfront.net/operator) with username `admin` and password `UYmnm5VIi6jM4WZRxXQozxeYS8_rwO1RWhb40p5E`. Do not make this repository public while these credentials are in the README.

The worker imports Kigali sector boundaries when the database is empty, then fetches weather data and scores sectors. It starts its first cycle shortly after startup and repeats about once an hour. Refresh the citizen page and select a sector. A current assessment shows its risk band, score, and update time. Assessments older than three hours appear as outdated.

If the map stays empty, check the worker logs. You can also sign in as an officer, open **Admin**, select **Import Kigali boundaries**, then select **Run weather ingestion**.

## Enable browser alerts locally

Browser push is optional. It needs a supported browser, notification permission, trusted HTTPS, and a persistent VAPID key pair. Generate a pair with Node.js 24 through Docker:

```bash
docker run --rm -i node:24-alpine node - <<'NODE'
const { generateKeyPairSync } = require("node:crypto");
const { privateKey } = generateKeyPairSync("ec", {
  namedCurve: "prime256v1",
});
const { x, y, d } = privateKey.export({ format: "jwk" });
const publicKey = Buffer.concat([
  Buffer.from([4]),
  Buffer.from(x, "base64url"),
  Buffer.from(y, "base64url"),
]).toString("base64url");

console.log("VAPID_PUBLIC_KEY=" + publicKey);
console.log("VAPID_PRIVATE_KEY=" + d);
NODE
```

Copy both output lines into `.env`, replacing the empty `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY` entries. Keep the private key secret and do not regenerate the pair after people subscribe. Apply the settings:

```bash
docker compose up -d --no-build backend worker
```

On the citizen page, choose a sector and select **Enable browser alerts**. Allow notifications when prompted. FloodGuard sends a confirmation notification so you can test that device without creating a fake flood event. Later notifications send when that sector enters High risk. Use **Turn off browser alerts** to unsubscribe that browser. Browser delivery is best effort and depends on browser and device settings.

## Common commands

| Task | Command |
| --- | --- |
| Show container status | `docker compose ps` |
| Show recent app logs | `docker compose logs --tail=100 backend worker` |
| Check backend health inside Docker | `docker compose exec backend curl -fsS http://localhost:8080/actuator/health` |
| Stop while keeping data | `docker compose down` |
| Start existing containers again | `docker compose up -d` |
| Rebuild after source changes | `docker compose up -d --build` |

**Do not use `docker compose down -v` as a normal stop command.** The `-v` flag deletes the database and other Compose volumes. That removes imported data, history, subscriptions, and the changed officer password. `docker compose down` preserves them.

### If you forgot the officer password

Run this from the project root:

```bash
docker compose run --rm -e RESET_ADMIN_PASSWORD=true backend --server.port=0
```

This resets the officer account to `ADMIN_PASSWORD` in your current `.env`. Sign in with that value, then set a new password when prompted. Do not add `RESET_ADMIN_PASSWORD=true` permanently to `.env`.

### If something does not start

- **Ports 80 or 443 are already in use:** Stop the other local service using those ports, then retry `docker compose up -d`.
- **Map is empty:** Check `docker compose logs --tail=100 worker`. The first GIS and weather requests need internet access. Use the officer Admin actions to retry them.
- **Browser alerts are unavailable:** Check that both VAPID keys are set in `.env`, restart `backend` and `worker`, and use a browser that supports push notifications over trusted HTTPS.
- **SMS signup is hidden:** This is expected while `SMS_ENABLED=false`. Browser alerts do not need Twilio.
- **Login keeps asking for a new password:** A newly created database requires one password change. After that, use the new password, not the original `.env` value.

## Data and optional integrations

FloodGuard loads Kigali sector boundaries from Rwanda's public GIS service and weather forecasts and historical rainfall from Open-Meteo. The basic local run needs no paid API credentials. Road geometry can be imported separately from Geofabrik after sectors are present. Use the current officer password you set after first sign-in:

```bash
printf "Current officer password: "
read -rs CURRENT_OFFICER_PASSWORD
printf "\n"
ADMIN_PASSWORD="$CURRENT_OFFICER_PASSWORD" docker compose --profile data run --no-deps --rm road-import
unset CURRENT_OFFICER_PASSWORD
```

The import may take time because it downloads the Rwanda road extract. Imported roads do not have verified flood vulnerability scores, and verified shelters must be supplied separately. See [data notes](docs/data-notes.md) before interpreting road or shelter results.

SMS and officer email are optional integrations. Their settings live in `compose.integrations.yaml`, which you can add with `docker compose -f compose.yaml -f compose.integrations.yaml up -d --build` after configuring the corresponding variables in a private `.env`. SMS requires a suitable Twilio sender and a consented delivery test. Browser alerts do not need these paid services.

Prometheus and Grafana are optional. To run them locally, add a strong `GRAFANA_ADMIN_PASSWORD` to `.env` and run `docker compose --profile monitoring up -d`; then open [https://localhost/grafana/](https://localhost/grafana/). ## Development without rebuilding the frontend container

The Docker setup remains the easiest way to run the backend and database. For frontend changes, install Node.js 24 and run:

```bash
cd frontend
npm ci
npm run dev
```

Open the Vite address printed in the terminal, normally `http://localhost:5173`. Its `/api` and `/ws` requests are proxied to the local Caddy service. For backend development, use Java 21 and `cd backend && ./mvnw test`.

This application is a classroom prototype. Validate its risk model, data sources, alert wording, delivery reliability, and operator procedures before using it for public safety decisions.
